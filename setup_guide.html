Чеклист настройки Шага 1:

  • Проверьте доступность порта HTTP сервера

    Убедитесь, что порт 8080 свободен на сервере. Если вы разворачиваете веб-интерфейс за прокси (Nginx), можете изменить порт на любой свободный (например, 8090).

  • Проверьте права на запуск TFTP сервера

    Поскольку TFTP использует системный порт 69, в ОС Linux вам потребуется запускать исполняемый файл от пользователя root или выдать файлу специальный capability: sudo setcap 'cap_net_bind_service=+ep' ./provisioning-system. Либо смените порт на непривилегированный (например, 6969) и настройте NAT перенаправление.

  • Задайте надежный пароль администратора (auth.admin_password)

    По умолчанию задан "password123". Обязательно смените его перед тем как подключить систему к корпоративной сети.

Настройка доменов и интеграции с АТС Mitel MX-One

В системе Provisioning System АТС Mitel MX-One привязана к конкретному домену (филиалу). IP-адрес АТС вынесен из глобальных настроек и привязан к домену как шлюз сигнализации и регистрации SIP.

⚠️
Логика выполнения deploy_commands и delete_commands

При создании/обновлении параметров телефона система генерирует файлы конфигурации и запускает deploy_commands. При удалении телефона запускаются delete_commands. В них используется шаблонизатор для подстановки параметров из интерфейса (номер телефона, описание, пароли).

Пример скрипта provision_subscriber.sh на сервере:

Данный скрипт должен быть расположен в рабочей директории системы и иметь права на исполнение. Он выполняет низкоуровневые команды АТС MX-One для регистрации абонента:

./provision_subscriber.sh (Скрипт для MX-One) 
#!/bin/bash
# Скрипт провиженинга абонента в MX-One

while getopts n:f:c:p: flag
do
    case "${flag}" in
        n) EXT=${OPTARG};;  # Extension / Номер
        f) DESC=${OPTARG};; # Full Name / ФИО
        c) CSP=${OPTARG};;  # CSP / Категория
        p) PASS=${OPTARG};; # Password / Пароль SIP
    esac
done

if [ -z "$EXT" ]; then
    echo "Error: Extension is empty"
    exit 1
fi

# Пути к исполняемым файлам CLI MX-One
MX_DIR="/opt/eri_sn/bin"

# 1. Создание абонента (если он еще не существует)
if ! $MX_DIR/extension -p -e $EXT >/dev/null 2>&1; then
    echo "Creating extension $EXT..."
    yes | $MX_DIR/extension -e -n $EXT -f "$DESC" -c $CSP
else
    echo "Extension $EXT already exists, skipping base creation."
fi

# 2. Создание IP/SIP параметров для этого абонента
if ! $MX_DIR/ip_extension -p -e $EXT >/dev/null 2>&1; then
    echo "Creating IP/SIP extension $EXT..."
    yes | $MX_DIR/ip_extension -e -n $EXT -p "N/A"
fi

# 3. Установка авторизационного пароля SIP-линии
if ! $MX_DIR/auth_code -p -e $EXT >/dev/null 2>&1; then
    echo "Setting SIP password/auth code for $EXT..."
    yes | $MX_DIR/auth_code -e -n $EXT -a "$PASS"
else
    echo "Updating SIP password for $EXT..."
    yes | $MX_DIR/auth_code -c -n $EXT -a "$PASS"
fi

echo "Subscriber $EXT successfully provisioned!"

Чеклист настройки Шага 2:

  • Создайте и сделайте исполняемым скрипт provision_subscriber.sh

    Сохраните код bash-скрипта выше в файл в корне проекта и выполните команду chmod +x provision_subscriber.sh.

  • Проверьте переменные домена в provisioning-system.yaml

    Убедитесь, что параметры sip_server1_ip и sip_proxy1_address указывают именно на сигнальный IP АТС MX-One (172.20.25.10).

  • Убедитесь в наличии прав для выполнения утилит MX-One

    Скрипт запускается от имени пользователя, указанного в Systemd сервисе. По умолчанию это должен быть mxone_admin или пользователь, входящий в группы с правами запуска утилит из /opt/eri_sn/bin/.

Настройка Вендора Mitel (структура папки conf/vendors/mitel)

Шаблоны конфигураций телефонов Mitel сгруппированы в директории conf/vendors/mitel/. Система автоматически сканирует эти каталоги при запуске и генерирует конфигурации.

📂
Карта директории Mitel

Убедитесь, что ваша папка вендора имеет следующий вид:

conf/vendors/mitel/
├── vendor.yaml           # Метаданные вендора Mitel
├── accounts.yaml         # Поля в интерфейсе добавления SIP-аккаунтов
├── templates/
│   ├── phone.tpl         # Главный Jinja/Pongo шаблон телефона (.cfg)
│   └── features.yaml     # Шаблоны функций кнопок (BLF, SpeedDial)
├── models/
│   ├── 6867i.yaml        # Описание кнопок и линий для Mitel 6867i
│   └── AnalogATS.yaml    # Описание аналоговых номеров (для MX-One)
└── static/               # Статические файлы прошивок и картинок

Главный шаблон телефона (templates/phone.tpl):

Этот шаблон рендерится для каждого телефона в системе. В нем используются циклы для обхода SIP-аккаунтов и функциональных кнопок:

conf/vendors/mitel/templates/phone.tpl 
{% if phone.type != "gateway" %}
# Mitel Phone-Specific Configuration ({{ account.mac_address|lower }}.cfg)
# Phone: {{ phone.type }} (Model: {{ phone.model }})
# User: {{ account.phone_number }}

# Account / Line Settings
{%- for line in account.lines %}
{%- if line.type == "line" %}
# ------------- line {{line.number}} --------------
sip line{{line.number}} user name: {{ line.user_name|default:line.number }}
sip line{{line.number}} auth name: {{ line.auth_name|default:line.number }}
sip line{{line.number}} password: {% if line.password -%}{{ line.password }}{%- elif variables.PasswdPre and variables.PasswdPost and (line.auth_name or line.phone_number) -%}{{ variables.PasswdPre }}{{ auth_name|default:line.phone_number }}{{ variables.PasswdPost }}{%- else -%}{{ variables.sip_password }}{%- endif %}
sip line{{line.number}} display name: {{ line.display_name|default:line.screen_name|default:line.number }}
sip line{{line.number}} screen name: {{ line.screen_name|default:line.display_name|default:line.number }}
sip line{{line.number}} proxy: {{ line.registrar_ip|default:variables.sip_server_ip }}
sip line{{line.number}} proxy port: {{ line.registrar_port|default:variables.sip_server_port|default:5060 }}
sip line{{line.number}} registrar: {{ line.registrar_ip|default:variables.sip_server_ip }}
sip line{{line.number}} registrar port: {{ line.registrar_port|default:variables.sip_server_port|default:5060 }}
{%- endif %}
{%- endfor %}

# Individual settings generated from lines and features
{%- for cfg in keys_config %}
{{ cfg }}
{%- endfor %}

# Custom Overrides and Additional Settings
{%- if phone.settings %}
# Device-specific settings
{%- for key, val in phone.settings %}
{{ key }}: {{ val }}
{%- endfor %}
{%- endif %}
{% else %}
# This device ({{ account.mac_address }}) is a {{ phone.type }} and does not require an individual configuration file.
# It is used for system number tracking and directory generation only.
{% endif %}

Чеклист настройки Шага 3:

  • Проверьте vendor.yaml для Mitel

    Убедитесь, что файл содержит правильное указание формата имени файла: phone_config_file: "{{account.mac_address|lower}}.cfg". Это важно, поскольку Mitel ожидает MAC-адрес в нижнем регистре без двоеточий.

  • Проверьте наличие необходимых моделей в models/

    В директории models/ должны быть описаны все используемые аппараты (например, 6863i, 6867i, а также виртуальная модель AnalogATS.yaml для учета аналоговых абонентов на MX-One).

  • Скопируйте шаблоны функций кнопок в templates/features.yaml

    Убедитесь, что в файле features.yaml заданы шаблоны для BLF, Speed Dial и XML-справочника.

Запуск системы и проверка работы

После настройки всех конфигурационных файлов, пришло время запустить систему, загрузить список телефонов (вручную или через импорт из Excel) и проверить, как АТС и аппараты взаимодействуют с сервером.

Команды для проверки работы в терминале:

Вы можете сгенерировать команды проверки для вашего IP-адреса сервера:

Проверка скачивания конфига по HTTP 
curl -v http://localhost:8080/configs/main_PBX/00085d1610de.cfg
Проверка скачивания конфига по TFTP 
tftp localhost -c get main_PBX/00085d1610de.cfg test_download.cfg
Проверка создания абонента на АТС MX-One 
/opt/eri_sn/bin/extension -p -e 1000  # Выведет информацию об абоненте 1000 на АТС
/opt/eri_sn/bin/ip_extension -p -e 1000 # Выведет IP/SIP статус абонента 1000

Чеклист настройки Шага 4:

  • Запустите сервис Provisioning System

    Используйте systemd: sudo systemctl start provisioning-system. Проверьте статус: sudo systemctl status provisioning-system.

  • Сделайте тестовый импорт из Excel

    Скачайте пример файла импорта из папки sample_config/Phones_IMPORT.xlsx. Заполните тестовую запись (MAC-адрес, номер, вендор="mitel", модель="6867i"), загрузите файл через веб-интерфейс в домен main_PBX.

  • Проверьте выполнение deploy_commands в логах

    При сохранении телефона откройте лог-файл (или journalctl -u provisioning-system -f) и убедитесь, что выполнился скрипт регистрации абонента на АТС: ./provision_subscriber.sh -n "..." -p "..." без ошибок.

  • Проверьте лог обращений (Debug) в веб-интерфейсе

    Перейдите во вкладку "Debug" (Логи обращений) в веб-панели. Вы должны увидеть запросы от телефонов Mitel на скачивание файлов конфигурации 00085dXXXXXX.cfg и статус ответа 200 OK.
